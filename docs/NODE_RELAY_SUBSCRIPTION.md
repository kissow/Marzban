## 行为与范围

用户实测旧版本额外的 `(Relay)` 条目可以联网、速度改善且出口仍为目标 Node；这是用户报告，不是维护者完成全矩阵公网压测。本轮只调整订阅，不改已可用的转发核心。

- 开启中转：在原 Hosts 条目上动态替换连接地址和端口，保留原别名、顺序和数量，不追加 `Node 名称 (Relay)`，不改用管理端节点名作为客户端别名。
- 关闭中转：恢复原条目的直连地址/端口。主服务器直出和其它 Node 不变。
- `/api/hosts` 持久化数据不改。原 UUID、HWID 独立凭据、REALITY 公钥、SNI、指纹、传输覆盖参数继续使用。
- 客户端地址/端口列会显示实际中转入口；不能在维持相同网络路径的同时伪造为目标 Node 地址。出口仍由目标 Node 的配置决定。
- 运行进程未就绪、匹配失败或歧义时保留原直连输出，不生成新条目；这不是自动保证直连公网可用。
- 原订阅生成器 short ID 选择改为当前输出副本，修复首次输出漏带 short ID 和修改共享入站对象的问题。

## 原 Host 匹配与管理 API

保持既有 sudo Bearer 权限及 GET `/api/nodes/relay/options`、GET/PUT/DELETE `/api/node/{node_id}/relay`，请求/响应字段、枚举不变。

按入站标签、规范化原 Host 地址与所选业务端口匹配 Node。原 Host 地址须与 Node 地址一致；不通过名称猜测、不解析 DNS 认定不同域名为同一 Node、不拆分混合多地址条目。多个原别名指向同一目标时分别保留并改写端点，数量不增不减。

PUT 新增校验：无匹配原 Host、混合地址无法确定目标、不同 Node 中转配置共用同一业务目的地返回 `422`，不应用新运行时、不写库。旧歧义记录周期恢复时显示明确错误并保留原订阅输出。端口/进程失败仍 `409`，数据库错误回滚合同不变。`original_direct_hosts_preserved=true` 指原持久化 Hosts 保留，不表示开启中转时再输出一个直连副本。

本轮无数据库迁移、无 Node 协议变更、无端口/证书/环境变更。Xray 固定 v26.3.27；Marzban-Node 与 scripts 无变化，不需本轮构建或服务器更新。
